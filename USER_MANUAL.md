# PDF to Editable PPT - User Manual (Hybrid OCR Edition)

## Overview

This tool converts PDF presentations (such as those generated by NotebookLM) into editable PowerPoint (.pptx) files while preserving the original background design. It uses a **Hybrid OCR approach** to solve the dual challenges of precise text positioning and accurate text recognition.

### Key Features

- ✨ **Background Preservation** - Maintains all visual elements from the original PDF.
- ✏️ **Hybrid OCR System** - Combines **RapidOCR** (for precise positioning) and **Qwen-VL LLM** (for accurate text correction).
- 🎨 **Smart Background Filling** - Automatically samples background colors to cover original image text naturally.
- 🖥️ **Modern Web Interface** - Premium glassmorphism-styled drag-and-drop UI.
- 🐧 **Linux Optimized** - Fully compatible with Linux environments for high-performance GPU processing.

## System Requirements

### General
- **Python 3.10+**
- **Node.js 18.0+** (Required for Vite 5+)
- **Modern Web Browser** (Chrome, Firefox, Edge)

### AI Backend (LM Studio)

- **LM Studio**: Installed and running on a reachable host
- **Supported Models**: Vision Language Models with vision + text understanding
  - `qwen2-vl-7b-instruct` (recommended for resource-constrained setups)
  - `qwen3-vl-30b-a3b-instruct` (higher accuracy, requires 24GB+ VRAM)
  - Other Qwen-VL variants with compatible API format
- **Server Configuration**:
  - Local Server mode enabled
  - Default listening port: 1234
  - API endpoint: `http://[server-ip]:1234/v1`
- **GPU Requirements**: Minimum 8GB VRAM (7B models), 24GB+ VRAM recommended (30B models)

## Linux Installation & Setup

If you are moving from Windows to Linux (e.g., a GPU server), follow these steps to ensure a clean deployment.

### Step 1: Prepare the Project
Copy the project folder to Linux, but **DO NOT** copy the `.venv` or `node_modules` folders.

### Step 2: Backend Setup (Python)
Navigate to the root directory and create a fresh virtual environment:

```bash
# Create and activate virtual environment
python3 -m venv .venv
source .venv/bin/activate

# Install required packages
pip install -r requirements.txt

# Additional OCR dependencies for Linux
pip install rapidocr_onnxruntime onnxruntime
```

### Step 3: Frontend Setup (Node.js)
Ensure you have Node.js 18+ installed. Using `nvm` is recommended:

```bash
# Install Node.js 18 via nvm (optional if already 18+)
nvm install 18
nvm use 18

# Install dependencies
cd frontend
npm install
```

## Configuration (LM Studio)

Edit `backend/pdf_processor.py` to match your LM Studio settings. **These values are environment-specific** and should be updated based on your deployment:

```python
# --- LLM OCR Setting ---
API_BASE_URL = "http://192.168.50.53:1234/v1"  # Your LM Studio server IP
API_KEY = "lm-studio"
MODEL_ID = "qwen3-vl-30b-a3b-instruct"  # Your loaded model ID
```

### Configuration notes

- **API_BASE_URL**: Replace `192.168.50.53` with your actual LM Studio server IP address
- **MODEL_ID**: Must match a model loaded in LM Studio (typically `qwen2-vl-7b-instruct`, `qwen3-vl-30b-a3b-instruct`, or similar)
- **API_KEY**: Keep as `"lm-studio"` (standard LM Studio default)
- **Timeout**: Set to 90 seconds in the current code for large models; adjust based on your GPU performance

## Technical Details: The Hybrid OCR Workflow

This version uses a sophisticated multi-phase system for precise text extraction and placement:

### Phase 1: Physical Positioning (RapidOCR)

RapidOCR scans the rendered page image to find the exact pixel coordinates (`bounding boxes`) of every text block. This ensures positional accuracy independent of PDF structure.

- Detects text regions with pixel-perfect precision
- Extracts initial OCR text (may contain recognition errors)
- Returns confidence scores for quality filtering (confidence > 0.3 threshold)

### Phase 2: Semantic Refinement (Qwen-VL LLM)

The page image and RapidOCR results are sent to the LLM for dual refinement:

- **Text Correction**: Fixes character recognition errors by analyzing the image context (handles code, CJK characters, complex layouts)
- **Bbox Adjustment**: Refines bounding box coordinates to fully contain text background areas with proper margins
  - Expands left/right for horizontal overflow (2-5 units)
  - Expands top for ascenders (1-3 units)
  - Expands bottom for descenders (1-2 units)

### Phase 3: Smart Background Filling

The tool prepares text placement with intelligent background handling:

- **Background Color Sampling**: Analyzes pixels around original text boxes (10% expanded region) to determine average background color
- **Solid Fill Overlay**: Applies matching background color as opaque text box fill, masking the original non-editable PDF text
- **Bbox Padding**: Applies configurable padding to final boxes (default: 3% horizontal, 2% top, 1% bottom) to ensure complete text background coverage

### Phase 4: Advanced Font Sizing

Uses iterative font size estimation instead of simple linear calculation:

- **CJK Character Awareness**: Distinguishes between CJK (wider ~1.0 em) and Latin (narrower ~0.5 em) characters
- **Dimension Fitting**: Considers both height and width constraints to find optimal font size
- **Bounds Enforcement**: Clamps font size between 8-72pt to maintain readability
- **Ascender/Descender Accounting**: Factors in typical typography proportions (80% of em-height is visible cap height)

### Phase 5: PowerPoint Generation with Proper Z-Ordering

Final slide assembly ensures correct visual hierarchy:

- **Text Boxes First**: All text elements are added before the background image
- **Background Behind**: Background image is reordered to Z-index position 2 (behind all text)
- **Vertical Alignment Control**: Text can be positioned as top-aligned, center-aligned, or bottom-aligned within boxes
- **Text Frame Margins**: 1pt internal margins provide fine-tuned padding within each text box

## Troubleshooting (Linux Specific)

### Node.js SyntaxError: Unexpected token {
**Cause**: Node.js version is too old (e.g., v10 or v12).
**Solution**: Upgrade to Node.js 18+ using `nvm install 18`.

### ModuleNotFoundError: No module named 'uvicorn'
**Cause**: Virtual environment not activated or dependencies not installed.
**Solution**: Run `source .venv/bin/activate` and `pip install -r requirements.txt`.

### TypeError: '>' not supported between instances of 'str' and 'float'
**Cause**: OCR engine returned confidence scores as strings.
**Solution**: Fixed in latest version (v1.5+). Ensure you have the updated `pdf_processor.py`.

### LLM OCR Failed / Timeout
**Cause**: LM Studio is not running or timeout is too short for large models.
**Solution**: Check if your GPU server IP is correct and LM Studio "Server" is ON. The timeout is set to 90s in the current code.
